# 奖励模块完整设计方案
# (Reward System Design · 让每一次自控都被看见、被积累、被庆祝)

> 目标：建立一套**数值自洽、成长可见、长期有追求**的奖励体系，把"省钱"这种延迟满足转化为即时的游戏化反馈，同时修复现有经济系统的漏洞。

---

## 一、现状问题诊断

| 问题 | 现状 | 后果 |
|---|---|---|
| EXP 获取途径少且随意 | 只有：冷静注冷 +15（无限刷）、拷问 +20~50（选理性就加）、放弃 +80、购买 +20 | 用户 10 分钟摸清套路，数值膨胀无感知 |
| 奖章逻辑名不副实 | 描述写"首次抵御冲动"，代码判定是 `defended >= 1 \|\| saved >= 100` | 只要省 100 元就解锁"首次抵御"，奖章廉价化 |
| 等级只有 6 级 | 6 级后无任何追求 | 长期用户失去目标 |
| 心愿兑换零成本 | 进度满即兑换，不扣金库余额 | 经济系统崩溃（已在决策模块修复，本方案接管奖励侧） |
| 无连胜/连续机制 | 放弃购买是孤立事件 | 缺少"连续 7 天未冲动消费"这类养成感 |
| 无负反馈 | 购买只有 +20 EXP 的"安慰奖" | 冲动残留者无代价，理性者觉得不公平 |
| 无展示与分享 | 奖章、等级只在自己 App 里看 | 缺少社交货币属性 |

---

## 二、设计原则

1. **奖励必须与努力正相关**：干预做得越多、克制得越久，奖励越大。
2. **奖励必须有层次感**：即时反馈（EXP）→ 中期目标（奖章/等级）→ 长期追求（心愿/成就墙）。
3. **数值必须守恒**：EXP 有明确产出与消耗途径；金库余额有进有出；奖章宁缺毋滥。
4. **奖励要可炫耀**：每一个成就都应该能生成图片分享，形成社交传播。

## 四、EXP 系统重做

### 4.1 EXP 产出表（与干预、决策模块完全对齐）

| 行为 | EXP | 限制 | 说明 |
|---|---|---|---|
| 完成一次深呼吸（3 轮） | +10 | 每日上限 3/5/8 次（按档位） | 生理平复 |
| 通过一道理智拷问 | +0（印记） | 每商品每关 1 次 | 印记在解冻时结算 |
| 提交冲动日记 | +5 | 每商品 1 次 | 自我认知 |
| 放弃购买（基础） | +50 | — | 理性胜利 |
| 放弃购买（印记加成） | +15 / 印记 | 最多 +60 | 4 个印记 = +60 |
| 放弃购买（完整冷静期） | +30 | 未提前破冰 | 鼓励耐心 |
| 放弃购买（冰川级额外） | +20 | 价格 > ¥2000 | 大额克制加成 |
| 确认购买（基础） | +20 | — | 完整冷静期的安慰奖 |
| 确认购买（冲动残留惩罚） | -5 / 次坚持破冰 | 最低 +5 | quizInsisted × 5 |
| 使用反馈"经常吃灰" | +15 | 购买 30 天后 | 诚实面对自己 |
| 连续克制每日奖励 | +5 | 连续天数 ≥3 时每日发放 | 连胜机制 |
| 心愿达成兑换 | +50 | 每心愿 1 次 | 长期目标达成 |

### 4.2 EXP 消耗途径（新增，解决数值膨胀）

EXP 不再只是"看"的数字，而是可以消费的货币：

| 消耗 | 花费 | 效果 |
|---|---|---|
| 提前解冻特权 | 200 EXP | 不等倒计时结束，直接进入决策（每件商品限 1 次） |
| 再冻一次特权 | 100 EXP | 突破"最多再冻 2 次"限制，额外再冻 24 小时 |
| 更换商品图片 | 50 EXP | 对抠图不满意的商品重新冰封 |
| 自定义奖章框 | 300 EXP | 金库页面的奖章展示框换肤 |
| 心愿加速充能 | 1 EXP = ¥1 等值 | 把 EXP 按 1:1 折算充入心愿（每月上限 500 EXP） |

> 消耗途径让 EXP 有"蓄水池"，用户会珍惜而不是无脑刷。

**实现补充**：`expToBalance(amount, wishId?)` 按上表「折算充入心愿」实现——
优先充进指定心愿，未指定时充进**进度最高**的未兑换且未充满心愿；心愿已满 / 当前无心愿可充时，
差额自动转入金库可用余额（不会凭空作废）。提前解冻 / 再冻一次 + 属于情景特权：
除 EXP 外还要求段位（提前解冻 Lv.5、再冻一次 + Lv.7），由 `constants/rewards.ts` 的
`EXP_PERKS[].minLevel` 单一维护；扣费结果区分 `level` / `exp` 两种失败原因，便于 UI 给出准确提示。

### 4.3 等级系统扩展

**现状**：6 级封顶。

**新方案**：12 级 + 称号系统。

| 等级 | 称号 | 所需 EXP | 所需累计节省 | 特权 |
|---|---|---|---|---|
| 1 | 萌新守门员 | 0 | 0 | — |
| 2 | 降温学徒 | 100 | 500 | — |
| 3 | 冰霜卫士 | 300 | 1500 | — |
| 4 | 钢铁意志 | 700 | 3500 | — |
| 5 | 理性大师 | 1200 | 8000 | 解锁"提前解冻"特权 |
| 6 | 欲望征服者 | 2000 | 15000 | — |
| 7 | 冰封领主 | 3000 | 25000 | 解锁"再冻一次 +"特权 |
| 8 | 冷静先知 | 4500 | 40000 | 金库页面专属皮肤 |
| 9 | 心智主宰 | 6500 | 60000 | 自定义奖章框 |
| 10 | 财务自由者 | 9000 | 100000 | 年度理性报告生成 |
| 11 | 欲望驯兽师 | 12000 | 150000 | 全部商品自动冰川级干预 |
| 12 | 生活炼金术士 | 16000 | 250000 | 称号展示 + 专属分享图 |

> 等级判定同时看 EXP 和累计节省，防止只刷小商品升级。

**实现补充（防止老玩家掉段）**：段位判定已改为 `exp >= minExp && saved >= minSaved`（AND）。
所有写库路径统一调用 `resolveDefenseLevel(currentLevel, saved, defended, exp) = max(已持有段位, 门槛算出段位)`，
因此：① 花 EXP（特权 / 心愿充能）不会让段位倒退；② 旧版本 OR 判定下发过的高段位会被保留（grandfathering），
只会升级不会降级。金库页面对应的两个进度条都夹在 `0..100`，避免出现 `width: -150%` 这类非法样式值。

## 五、奖章系统重做

### 5.1 判定逻辑修复

**现状**：代码用 `defended >= x \|\| saved >= y`（OR），描述却是"首次/3 次/5 次抵御"。

**修复**：严格区分"次数类"和"金额类"，按类型判定：

```ts
export interface AchievementMedal {
  id: string;
  name: string;
  description: string;
  iconKey: string;
  type: 'count' | 'saved' | 'streak' | 'perfect' | 'special';
  requiredDefended?: number;   // type='count'
  requiredSaved?: number;      // type='saved'
  requiredStreak?: number;     // type='streak' 连续天数
  requiredPerfect?: number;    // type='perfect' 完美克制次数
}
```

### 5.2 奖章清单（重做 + 新增）

| 奖章 | 类型 | 条件 | 描述 |
|---|---|---|---|
| 青铜盾甲 | count | defended ≥ 1 | 首次成功抵御冲动消费 |
| 黄金屏障 | count | defended ≥ 3 | 成功抵御 3 次非理性剁手 |
| 钻石心盾 | count | defended ≥ 10 | 十次理性胜利（新增） |
| 耐心铜勋 | saved | saved ≥ 500 | 累计省下 ¥500 |
| 定力银勋 | saved | saved ≥ 3000 | 累计省下 ¥3,000 |
| 金库富翁 | saved | saved ≥ 10000 | 累计省下 ¥10,000 |
| 三日清心 | streak | 连续 3 天无购买 | 新增连胜奖章 |
| 七日禅 | streak | 连续 7 天无购买 | 新增 |
| 月度圣人 | streak | 连续 30 天无购买 | 新增 |
| 完美克制 · 铜 | perfect | 1 次完美克制 | 新增 |
| 完美克制 · 银 | perfect | 3 次完美克制 | 新增 |
| 完美克制 · 金 | perfect | 10 次完美克制 | 新增 |
| 冰川征服者 | perfect | 1 次冰川级完美克制 | 新增：>¥2000 商品完美克制 |
| 心愿实现家 | special | 首次心愿兑换 | 新增 |
| 理性生活家 | special | 兑换 3 个心愿 | 新增 |

**"完美克制"定义**：一件商品冷冻期间满足：① 集齐全部理性印记；② 未提前破冰；③ 最终选择放弃。这是最高荣誉，奖励结算时 EXP 额外 +50。

## 六、连胜系统（新增）

**目的**：把"单次放弃"升级为"连续克制"的养成感。

**规则**：
- 每日判定：当天没有任何冷冻商品被标记为 `thawed_purchased`，则连胜天数 +1。
- 连胜 ≥3 天：每日首次打开 App 显示连胜火焰 🔥 +5 EXP。
- 连胜 ≥7 天：金库页面显示"七日禅"进度条。
- 购买行为会**清零连胜**，但显示"连胜中断，从头再来"而非惩罚性文案。
- 数据存 `VaultStats.currentStreak` + `VaultStats.lastStreakDate`。

**防作弊**：连胜判定基于自然日，而非 App 打开时间。

## 七、成就墙与分享（新增）

### 7.1 年度理性报告

每年 12 月 31 日或用户满 1 周年时生成：
- 累计冷冻商品数、放弃率、最常冷冻品类
- 节省总金额、相当于工作多少小时
- 冲动画像（场景分布、情绪分布）
- 与全国用户的对比（假数据占位，未来接后端）
- 生成精美图片，一键分享

### 7.2 单次战报分享

每次放弃购买后的 `VictorySettlement` 卡片支持：
- 保存为图片（`react-native-view-shot`）
- 分享到微信/朋友圈/微博（系统分享）
- 文案模板："我用 48 小时冷静期，成功抵御了 ¥5,999 的冲动消费！#冲动消费冷冻箱"

## 八、心愿金库联动（奖励侧）

配合决策模块的经济修复，奖励模块负责"庆祝时刻"：

- 心愿进度每跨 25%：心愿卡片金光闪烁 + `HapticsService.lightTap()`。
- 心愿达成 100%：全屏金色雨动画 + `AudioService.playFanfareSound()` + "心愿达成！"自定义 Modal。
- 心愿兑换：EXP +50，奖章"心愿实现家"解锁，生成分享卡片："我用省下的冲动消费金，实现了「海岛旅行」心愿！"

## 十一、验收标准（Definition of Done）

1. EXP 有明确的产出表和消耗表，所有 EXP 变动都经过 `services/rewards.ts` 并记录流水。
2. 奖章按 5 种类型判定，不再出现"省 100 元解锁首次抵御"的错位。
3. 等级扩展到 12 级，每级有明确的 EXP + 累计节省双重要求。
4. 连胜系统：连续 3 天无购买后每日首次打开有火焰动画和 +5 EXP。
5. "完美克制"有明确定义（4 印记 + 未提前破冰 + 放弃），达成后 EXP 额外 +50。
6. EXP 商店可用：200 EXP 提前解冻、100 EXP 额外再冻、EXP 充心愿等功能正常。
7. 心愿达成 100% 时有全屏金色雨 + 号角音效，兑换后 +50 EXP 并解锁奖章。
8. 放弃购买后的战报卡片可保存图片并分享。
9. 金库页面新增"成就墙"Tab，展示所有奖章（已解锁点亮，未解锁灰色）。
